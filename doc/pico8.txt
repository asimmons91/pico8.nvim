*pico8.nvim* *pico8*

Neovim client for pico-lsp, a PICO-8 language server.

==============================================================================
INSTALL                                                   *pico8-install*

Requirements ~
                                                      *pico8-requirements*
- Neovim 0.11.4 or newer. This release is tested with 0.11.4 and 0.12.6.
- `pico-lsp` v1.8.1 or newer. A release archive does not require Go.
- Optional: a C compiler for |:Pico8InstallParser| (Tree-sitter).
- PICO-8 0.2.7 is only needed to run carts. The plugin does not run them.

Install the server from the `pico-lsp` release page or with Go 1.27.4+:
>sh
    go install github.com/asimmons91/pico-lsp/cmd/pico-lsp@v1.8.1
<
A lazy.nvim plugin spec: >lua
    {
      "asimmons91/pico8.nvim",
      tag = "v0.1.0",
      main = "pico_lsp",
      lazy = false,
      opts = {},
    }
<
Neovim 0.12+ also supports: >lua
    vim.pack.add({
      { src = "https://github.com/asimmons91/pico8.nvim", version = "v0.1.0" },
    })
    require("pico_lsp").setup()
<
There is no `plugin/` entry. Keep the plugin on 'runtimepath' and call
`require("pico_lsp").setup()` once; that registers commands, starts the
included-Lua helper, and installs PNG auto-open. Keep 'filetype plugin' on.

Full install, upgrade, uninstall, and Tree-sitter instructions are in
`docs/install.md`. The five-minute path is in `docs/getting-started.md`.

==============================================================================
SETUP                                                         *pico8-setup*

Call: >lua
    require("pico_lsp").setup()
<
The default setup enables the `pico_lsp` client for `pico8` buffers and starts
the helper for cart-owned `.lua` files. The shipped config is loaded from
`lsp/pico_lsp.lua` on 'runtimepath'; loading it also registers the cached cart
statusline module and its commands (see |pico8-statusline|).

`.p8` buffers use the cart's directory as the workspace root, even outside a
git repository. Carts in different directories use separate clients. Override
`root_dir` with `vim.lsp.config("pico_lsp", { ... })` before opening a cart
for repository-wide symbols.

A loaded cart buffer is the helper's include source. Reload an open cart with
`:edit!` after an external change; the helper rescans on reload.
`:Pico8Refresh` clears cached include data and rescans loaded `.lua` buffers;
it does not reload a cart buffer. The helper only detaches attachments it
created; a client started by the user is left alone.

A managed include keeps `filetype=lua`. When it still has stock Lua comment
settings, the helper sets `comments=:---,:--,://` so `//` is recognized by
comment formatting, and `commentstring=--\ %s` so `gcc` uses `--`. Custom values
are not overwritten on attach. Managed detach, including disabling the helper,
restores only the values the helper changed and only if they are still in
place. A later change to a different value is kept; an option set to exactly
the PICO-8 target is restored. Restore records are module-local, so after a
plugin reload a later detach leaves exact PICO-8 values in place.
`b:pico8_cart` holds the owning cart URI and `b:pico8_cart_root` its directory.

Options:                                                      *pico8-options*
    `cmd`           server command (string, list, or function)
    `lsp`           enable the client during setup (default true)
    `disable`       disable the helper and LSP setup
    `codelens`      enable client-side budget lens display (default true)
    `inlay_hints`   enable client-side inlay-hint display (default true)
    `glyph_maps`    install Shift-A..Z glyph maps (default false)
    `settings`      pico8 server settings table

The shipped config enables the client-side display for the cart budget lens
and inlay hints on `pico8` buffers. The server's `pico8.limits.codeLens` and
`pico8.inlayHints` settings decide what is returned; hints also require type
checking to be enabled. See the pico-lsp configuration reference for defaults.
Client-side options apply to clients started afterwards. Restart Neovim after
changing server settings; `:lsp restart` on Neovim 0.12+ is enough for the
display options.
`:Pico8ToggleInlayHints` toggles the display for a buffer and warns when the
server setting is false or absent.

The server owns setting defaults; the plugin does not duplicate them. The
command falls back from `g:pico_lsp_cmd` to `$PICO_LSP_BIN` to `pico-lsp`.

A lazy.nvim spec: >lua
    { "asimmons91/pico8.nvim", main = "pico_lsp", lazy = false, opts = {} }
<

STATUSLINE                                                 *pico8-statusline*

The helper caches `pico8/cartInfo` for a root cart, an included `.lua` buffer,
or a decoded `.p8.png` buffer: >lua
    local api = require("pico_lsp")
    api.cart_status()            -- cached text, or nil before the first response
    api.cart_info()              -- full cached cartInfo table
    api.refresh_cart_info()      -- asynchronous refresh
<
`cart_status()` only reads the cache and never blocks on the server. It updates
after an attach, `:w`, `InsertLeave`, and a 500 ms edit debounce. The compressed
segment is omitted when `compressedStatus` is `unavailable`, as it is for
standalone `.lua` carts. Pass `{ fields = { "tokens", "chars" } }` to select
segments.

A dependency-free statusline example: >lua
    function _G.Pico8CartStatus()
      return require("pico_lsp").cart_status() or ""
    end
    vim.o.statusline = "%f %m %{%v:lua.Pico8CartStatus()%} %= %l:%c"
<
`cart_info().compressedStatus` is `ok`, `warning`, `error`, or `unavailable`.
Statusline plugins can use it to color the component. A lualine recipe is in
`README.md`.

INCLUDES                                                   *pico8-includes*

The `pico8` ftplugin sets buffer-local 'include', 'includeexpr', and 'path'
options, so |gf|, |CTRL-W_f|, and |CTRL-W_gf| open `#include` targets without
helper setup or a running client. A relative target resolves against the cart's
directory, not the current directory; absolute paths stay absolute. 'path' is
scoped to the cart so a plain relative name cannot win from the working
directory. A custom 'path', including one set by an after-ftplugin or `FileType`
handler, is preserved, and the scoped path follows `:saveas`/`:file` renames.
Names starting with `./` or `../` are handled by Vim relative to the working
directory before 'includeexpr'. Cart directories containing glob characters
(`[`, `]`, `*`, `?`, or `$`) use 'includeexpr' instead of Vim's raw lookup.

Supported forms include quoted, unquoted, whitespace-padded, nested, and
space-containing paths. A trailing `:<hex digit>` is stripped only for `.p8`
and `.p8.png` targets, matching the server. A `.lua:2` filename stays literal.
|gf| opens the file at its start, not at a code tab; use |:Pico8Tabs| for tabs.
Missing targets report the normal `E447`/`E484` error and create no file.

Vim tries its unmodified-name lookup before 'includeexpr'. A quoted path whose
first word is also a file in the cart can therefore open that file; rename it or
use `:edit` with the full path in that rare case.

The defaults are installed only for empty options. A buffer-local
'includeexpr' is preserved as a user value. 'include' is global-local, so a
global value is a default and is overridden locally, then restored by the
ftplugin undo hook.

FORMATTING AND LINKS                                      *pico8-formatting*

A server build with M33 advertises standard range formatting, so Neovim sets
'formatexpr' for `pico8` buffers. |gq| formats the complete lines covered by the
selection through `textDocument/rangeFormatting`; a single-line selection
formats that line. `pico-lsp` v1.8.1 predates M33, so with that release |gq| is
not configured and |gx| below is unavailable. The server formats the whole document for context but returns edits only
for the selected lines, and non-code cart sections are preserved. The PICO-8
formatter does not wrap long lines, so |gq| changes layout and spacing rather
than reflowing comment text.

A range that would change the line count is refused and the buffer is left
unchanged. Format the whole document instead: >vim
    :lua vim.lsp.buf.format()
<

On Neovim 0.12 and newer, |gx| on an `#include` target uses the server's
document link and passes the resolved file to |vim.ui.open()|, which uses the
system opener. It does not open a Neovim buffer. |gf| remains the in-editor
navigation path and works on Neovim 0.11+.

P8SCII GLYPHS                                                *pico8-glyphs*

The client caches the `pico8/glyphs` catalog per `pico_lsp` client and cart
root. Enable the optional Shift maps with `glyph_maps = true` in setup or with
`g:pico8_glyph_maps = 1`. The catalog is prefetched after attach; Shift-A..Z
read the cached byte map and fall back to literal uppercase letters outside the
`__lua__` section, in `#include` paths, in replace mode, in read-only buffers,
or without a client. A cold cache makes one bounded request and warns once per
client if it fails.

|:Pico8InsertGlyph| accepts an exact name (`left`), a decimal byte (`139`), or
a hex byte (`0x8b`). Any other argument opens |vim.ui.select| filtered by a
case-insensitive substring across the name, description, and byte spellings.
Command-line completion lists cached canonical names without a request. Byte
values outside 0..255 are rejected before the server is called. Control glyphs
remain string-only, and the server rejects insertion outside Lua code or in an
`#include` path.

Changing `pico8.glyphs` requires a client restart so the cache is cleared and
the new catalog is fetched.

PNG CARTS                                                     *pico8-png*

With the helper enabled, opening a PNG cart directly decodes it: >sh
    nvim path/to/cart.p8.png
<
The original binary PNG buffer is removed after a successful decode. On a
decode or client-start failure, the buffer becomes an empty, read-only
`nofile` buffer with its name intact; raw binary data is never shown. Retry
with |:Pico8OpenPng|. The command offers file completion. Reopening the same
PNG with `:edit`, `:split`, or |:Pico8OpenPng| reuses its virtual buffer and
preserves buffer-local include/expression/path values. A `:bdelete`d or
unloaded virtual cart restores its virtual options when loaded again; a stale
restore lists the cart. |:Pico8ReloadPng| restores its text and client and
keeps a deliberately unlisted buffer unlisted. The virtual buffer carries
`b:pico8_cart_root` and a scoped 'path', so |gf| resolves includes against the
PNG's directory.

Auto-open is installed only by `require("pico_lsp").setup()` when the helper is
enabled. A disabled setup installs no PNG autocmd, and the shipped
`lsp/pico_lsp.lua` config alone does not auto-open PNGs.

TREE-SITTER                                                *pico8-treesitter*

The Vim syntax file works without a compiler. Build and install the optional
editor-only Tree-sitter parser and queries from the vendored grammar: >vim
    :Pico8InstallParser
<
The command installs under `stdpath("data")/site`: >text
    parser/pico8.so                 (pico8.dll on Windows)
    queries/pico8/highlights.scm
    queries/pico8/indents.scm
    queries/pico8/textobjects.scm
<
It adds `site` to 'runtimepath' once and registers `pico8` in the current
session. Repeated runs skip an up-to-date parser and repair changed queries.
|:Pico8InstallParser!| forces a rebuild; a failed rebuild leaves the previous
parser and queries usable. After a forced rebuild, restart Neovim to load the
new binary in a session that already loaded the old one.

The grammar directory resolves from `g:pico8_treesitter_source`, then
`$PICO_LSP_TREE_SITTER`, then `vendor/tree-sitter-pico8` in the plugin. The
compiler resolves from `$CC`, then `cc`, then `clang`; `$CC` is one executable
path. Compilation is bounded to 60 seconds and installs atomically.

The installer never starts highlighting. Start it for `pico8` buffers: >lua
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "pico8",
      callback = function()
        pcall(vim.treesitter.start, 0, "pico8")
      end,
    })
<
The grammar is editor highlighting only; LSP diagnostics, completion, and
semantic tokens stay server-owned. The parser targets ABI 14 for Neovim 0.11+.
See `docs/install.md#tree-sitter` for the manual build fallback.

HEALTH CHECK                                                *pico8-health*

Run `:checkhealth pico_lsp` for a read-only report of the plugin. It covers
the Neovim version, `vim.lsp.config` presence, the resolved command and its
source, the server binary and `--version` probe, running clients and their
roots, client-side code-lens and inlay-hint state, helper-managed `.lua`
buffers, helper commands, and Tree-sitter availability. Install the parser with
|:Pico8InstallParser|; health only reports it.

Health does not start or stop clients, download a binary, install a parser,
edit a buffer, or change configuration. The only process it runs is the
configured binary with `--version`, with a 2-second timeout. A function-valued
`cmd` is reported but never called. See `docs/troubleshooting.md` for how to
read the report.

COMMANDS                                                   *pico8-commands*

:Pico8OpenPng [path]     Decode a `.p8.png` cart into a read-only buffer;
                         offers file completion.                *:Pico8OpenPng*
:Pico8ReloadPng          Reload the current decoded PNG cart.
                                                             *:Pico8ReloadPng*
:Pico8InsertGlyph [name|byte|search]
                         Insert a P8SCII glyph by name or byte, or open a
                         filtered picker. Completes cached names.
                                                          *:Pico8InsertGlyph*
:Pico8Refresh            Clear the include cache and rescan loaded buffers.
                                                              *:Pico8Refresh*
:Pico8ToggleInlayHints   Toggle client-side inlay hints for this buffer.
                                                       *:Pico8ToggleInlayHints*
:Pico8CartInfo           Request and show the cart budget with file detail.
                                                            *:Pico8CartInfo*
:Pico8Tabs               Pick a code tab and jump to its start line.
                                                                *:Pico8Tabs*
:Pico8OpenCart           Open the cart that owns the current include buffer.
                                                            *:Pico8OpenCart*
:Pico8InstallParser[!]   Build and install the Tree-sitter parser and queries;
                         `!` forces a rebuild. See |pico8-treesitter|.
                                                       *:Pico8InstallParser*

`:checkhealth pico_lsp` reports plugin state without changing it; see
|pico8-health|.                                      *:checkhealth-pico_lsp*

`:Pico8Tabs` explains that tabs belong to the owning cart on an included `.lua`
buffer, and jumps inside the virtual buffer for a decoded `.p8.png` cart.
`:Pico8OpenCart` opens the owner in the current window. It reports that the
buffer is already a cart on a cart or decoded `.p8.png` buffer, and reports no
owner on an unrelated buffer.

VARIABLES                                                 *pico8-variables*

`g:pico8_glyph_maps`     Enable Shift-A..Shift-Z glyph maps. The
                         `glyph_maps` setup option is equivalent.
`g:pico8_treesitter_source` Override the Tree-sitter grammar directory.
`g:pico_lsp_cmd`         Override the server command.
`g:pico_lsp_helper_disabled` Disable the included `.lua` helper.
`b:pico8_cart`           Owning cart URI on a managed include.
`b:pico8_cart_root`      Cart directory on a managed include or decoded PNG.
